# Learn

## Inputs

- **Focus**: an optional package, directory, or topic to narrow the capture.
- **Guidance**: any remaining text says what to emphasize.

## 1. Find the guidance files

- Agent guidance file: `AGENTS.md` if the repo has one, otherwise `CLAUDE.md`, otherwise the harness's own file. If that file is generated by Rulesync (`rulesync.jsonc` enables the `rules` feature and `.rulesync/rules/` exists), edit the matching `.rulesync/rules/*.md` source instead, never the generated file.
- If a guidance file is generated or symlinked from another, edit the source.

## 2. Harvest

Scan the session for things a future agent would otherwise get wrong:

- hidden relationships, or files that must change together
- execution paths that differ from how the code reads
- non-obvious config, env vars, flags, or required setup
- debugging breakthroughs where the error message misled
- tool/API quirks and their workarounds
- validation steps that are not documented elsewhere
- decisions and constraints that are not visible in the code

Discard: obvious or standard behavior, things already documented, things derivable from code or `git log`, and one-off session details.

## 3. Place and write

- Put each learning at the most specific scope where it applies: repo root, package (`packages/foo/AGENTS.md`), or feature directory.
- Read the target file first. Update an existing bullet instead of duplicating it, and correct anything the session proved wrong.
- Write 1-3 actionable lines per learning, in imperative voice, under an existing section when one fits.
- Create a new nested file only for a real scope boundary.

If nothing qualifies, say so and change nothing.

## Output

```text
Learnings for <focus | this session>
- <file>: <n> added, <n> updated
```
