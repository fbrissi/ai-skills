# Contributing

Requires Node.js 22.22+ (Rulesync), plus `bash`, `git` and `jq`.

## Layout

```text
.rulesync/
├── rules/overview.md              # repo guidance → AGENTS.md, CLAUDE.md, ...
├── subagents/<name>.md            # agents → .claude/agents/, the plugin, and .opencode/agents/
└── skills/<name>/
    ├── SKILL.md                   # source of truth for the skill
    ├── references/*.md            # skill's own, or COPIED from shared/ when listed in manifest.txt
    └── scripts/*                  # skill's own, or COPIED from shared/ when listed in manifest.txt
shared/
├── manifest.txt                   # which shared file goes into which skills
├── references/                    # tickets.md, body-format.md, commits.md
└── scripts/pr-context.sh
scripts/
├── sync-shared.sh                 # copies shared/ into skills; --check detects drift and orphans
├── copy-opencode-agents.sh        # copies .opencode/agents/ into plugins/ai-skills/opencode/agent/ (part of generate)
├── check-generated.sh             # fails if rulesync would change tracked outputs (works without gitignored folders)
└── check-discovery.sh             # asserts the skills CLI finds every skill
.github/workflows/                 # CI, code review, releases (tracked, not generated)
plugins/ai-skills/                 # Claude Code plugin: agents/ and skills/ generated and committed
├── opencode/agent/                # OpenCode agents, generated and committed
└── .claude-plugin/plugin.json     # hand-written; version must match package.json
.claude-plugin/marketplace.json    # marketplace that lists the plugin
rulesync.jsonc                     # project generation (delete: true)
rulesync.global.jsonc              # dev preview in user folders (delete: false, never change)
CHANGELOG.md                       # drives releases
docs/
```

Generated by `npm run generate` (never edit by hand):

- `AGENTS.md` and `CLAUDE.md` are committed, so agents and contributors get the repo guidance from a plain checkout. Edit `.rulesync/rules/overview.md`, regenerate, and commit both; `npm run check` fails if they are stale. They are unignored after the Rulesync block in `.gitignore`.
- `.claude/`, `.agents/`, `.cursor/`, `.opencode/`, `.github/skills/` and `.github/copilot-instructions.md` are gitignored. Keep them out of git: the `skills` CLI discovers the skills in `.rulesync/skills/`, and committed harness folders would make it list each skill again.

Do not run `rulesync gitignore` with other settings or remove its block from `.gitignore`.

Why the copies: the `skills` CLI and `rulesync install` fetch one skill directory at a time (and Rulesync skips symlinks), so every skill must carry real copies of the files it uses. Edit `shared/`, never the copies.

## Skill rules

- Frontmatter has only `name` (equal to the folder) and `description` (what it does plus "Use when…"). Do not add Rulesync's `targets` key: it is optional and would ship to every user.
- No harness tool names in the body. Skills that hand off to another skill include a fallback for when it is not installed.
- Scripts are run by absolute path from the user's repository root, never from the skill folder.
- Keep project-specific values out of skills: read them from a [project profile](README.md#project-profiles) and ship `references/profile-template.md`.

## Workflow

1. Branch from `main`.
2. Add or edit `.rulesync/skills/<name>/SKILL.md` (the `skill-authoring` skill guides this).
3. To share a file, put it in `shared/` and list the target skills in `shared/manifest.txt`.
4. Run:
   ```bash
   npm run generate
   ```
   ```bash
   npm run check
   ```
   ```bash
   npm run check:discovery
   ```
5. For a new skill, add `docs/skills/<name>.md`, a row in the [catalog](README.md), and the skill in the root [README](../README.md) table. For a new agent, add it to [claude-code-agents.md](claude-code-agents.md) and the root README agents table.
6. Add a release entry at the top of [CHANGELOG.md](../CHANGELOG.md) and bump `version` in `package.json` and `plugins/ai-skills/.claude-plugin/plugin.json` to match (see below).
7. Open a pull request against `main`.

## CI and releases

| Workflow | Trigger | What it does |
| --- | --- | --- |
| `quality-checks.yml` | PRs, pushes to `main` | `npm run check`, `npm run doctor`, `bash -n` and `ruby -c` on scripts, `check:discovery`, `npm audit`; on PRs to `main`, the release-note check; then dispatches Code Review and QA in parallel |
| `code-review.yml` | dispatched by Quality Checks on `main` | Calls the shared [Code Review](https://github.com/fbrissi/github-actions#code-review) workflow: OpenCode or Claude Code (`AI_HARNESS`) with this repo's `review-changes` skill (taken from the base commit) publishes a PR review; its `join` job then joins it with QA |
| `qa.yml` | dispatched by Quality Checks on `main` | Calls the shared [QA](https://github.com/fbrissi/github-actions#review-and-qa-in-separate-jobs) workflow (`qa-e2e`, targeted validation): publishes the `AI QA` check and joins it with the review |
| `pr-feedback.yml` | PR review submitted | Calls the shared quality join: once the `Code Review` and `AI QA` checks of the head have completed, dispatches PR Fix when either asks for changes and Merge Decision when both approve |
| `pr-fix.yml` | dispatched by the quality join on `main` | Calls the shared [PR Fix](https://github.com/fbrissi/github-actions#pr-fix) workflow on `hotfix/` and `bugfix/` branches or PRs labeled `ai:auto-fix`: fixes the review threads and the QA report and pushes; after 3 passes it adds `ai:needs-human` |
| `merge-decision.yml` | dispatched by the quality join on `main` | Calls the shared [Merge Decision](https://github.com/fbrissi/github-actions#merge-decision) workflow on the same branches with `auto-merge: false`: rates the risk with `merge-risk` and holds; a person merges after approving the head commit |
| `ai-dependency-update.yml` | weekly, Monday 15:00 UTC, or manually | Runs the shared `dependency-update` AI task (profile [`docs/ai/dependency-updates.md`](ai/dependency-updates.md)) with `quality-mode: separate`: it only develops and opens the `hotfix/` and `bugfix/` PRs, and the loop above follows up |
| `release-orchestrator.yml` | PR merged into `main` | Calls the shared [release](https://github.com/fbrissi/github-actions#release) workflow, which tags the top `## vX.Y.Z` of `CHANGELOG.md` and creates the GitHub release |
| `release.yml` | run manually | Runs the same shared release workflow for a given version |

**Release notes**: every PR into `main` must add exactly one new heading `## vMAJOR.MINOR.PATCH` at the top of `CHANGELOG.md`, with notes, for a version that has no tag yet. `package.json`'s `version` must match. Merging the PR tags and releases that version. Users then get it with `npx skills update`, or pin it with `npx skills add fbrissi/ai-skills@vX.Y.Z`.

**Code Review setup** (repository settings):

| Name | Kind | Purpose |
| --- | --- | --- |
| `AI_HARNESS` | variable | `claude` (default when empty) or `opencode` |
| `AGENT_APP_CLIENT_ID`, `AGENT_APP_PRIVATE_KEY` | variable, secret | GitHub App that reviews, tests, fixes, and rates: Contents and Pull requests read and write, Issues read, Checks read, Actions read, and Commit statuses read; never Workflows |
| `OPENCODE_MODEL`, `OPENCODE_VARIANT` | variables | OpenCode model (`provider/model`) and variant; `OPENCODE_MODEL` is required for `opencode` |
| `OPEN_AI_TOKEN` | secret | Provider key used by OpenCode |
| `CLAUDE_MODEL`, `CLAUDE_EFFORT` | variables | Optional Claude Code model and effort |
| `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY` | secret | Claude Code authentication; one is required for `claude` |
| `CODE_REVIEW_ENABLED` | variable | `false` skips the review |
| `CI_RUNNER` | variable | Optional runner label |

The review, QA, fix, and merge decision jobs run in the `code-review` environment, which GitHub creates on the first run; add protection rules there if you want them. A review that ends with `Published: skipped (...)` passes without publishing. The labels `ai:auto-fix` (opts a PR into PR Fix), `ai:needs-human` (PR Fix escalation), and `ai:needs-approval` (a sign-off before the merge decision) must exist.

## Commands

| Command | What it does |
| --- | --- |
| `npm run sync` | Copy `shared/` files into skills and remove orphaned copies |
| `npm run generate` | Sync, then generate project outputs |
| `npm run check` | Fail if shared copies (content, exec bit, orphans) or generated outputs (including the plugin) are stale, or the plugin version differs from `package.json` |
| `npm run check:discovery` | Fail if the `skills` CLI does not find every skill |
| `npm run doctor` | Diagnose the Rulesync config |
| `npm run generate:global` | Dev preview: write the skills into `~/.claude/skills` and `~/.agents/skills` (never deletes other skills). Do not mix with `npx skills add -g`, which manages the same folders |

`sync-shared.sh` and the npm scripts are bash: on Windows, use Git Bash or WSL.
